工作流程

  1. 启动目标: 浏览器通过 `--remote-debugging-port` 参数开启调试服务。
  2. 后端连接: Node.js 代理服务通过 WebSocket 连接到浏览器暴露的调试地址。
  3. 前端连接: 用户打开的前端 UI 应用，再通过 WebSocket 连接到我们的 Node.js 代理。
  4. 命令与事件流转: 所有操作指令和状态事件都在这条链路中双向传递，完成调试闭环。

核心协议: Chrome DevTools Protocol (CDP)

CDP 是整个调试工具的基石。它是一个基于 WebSocket 的 JSON-RPC 协议，定义了与浏览器内核交互的标准化命令和事件。协议按功能划分为不同的“域”（Domains），如 DOM、Debugger、Network 等。

核心功能实现路径

每个 DevTools 功能面板的背后，都是一系列精心设计的 CDP 命令和事件监听。这里展示了几个核心功能的实现逻辑。

元素审查 (Elements Panel)

  • 获取 DOM 树: 调用 `DOM.getDocument` 获取完整节点树。
  • 监听变化: 监听 `DOM.setChildNodes` 等事件来实时更新 UI。
  • 高亮节点: 调用 `DOM.highlightNode` 在目标页面高亮显示元素。
  • 获取样式: 调用 `CSS.getComputedStyleForNode` 获取计算样式。

控制台 (Console Panel)

  • 显示日志: 监听 `Runtime.consoleAPICalled` 事件来捕获 `console.log` 等输出。
  • 执行代码: 调用 `Runtime.evaluate` 在目标页面上下文中执行任意 JavaScript 表达式。

源代码调试 (Sources Panel)

  • 加载脚本: 监听 `Debugger.scriptParsed` 事件，然后调用 `Debugger.getScriptSource` 获取源码。
  • 设置断点: 调用 `Debugger.setBreakpointByUrl` 在指定行设置断点。
  • 控制执行: 监听 `Debugger.paused` 事件，并提供 `resume`, `stepOver` 等操作。

网络监控 (Network Panel)

  • 开启监控: 调用 `Network.enable` 开始捕获网络活动。
  • 监听生命周期: 监听 `Network.requestWillBeSent`, `Network.responseReceived`, `Network.loadingFinished` 等一系列事件。
  • 获取内容: 调用 `Network.getResponseBody` 获取请求的响应体。

阶段一: 基础通信

搭建前后端 WebSocket 通信，打通命令发送和结果回显的闭环。

阶段二: 实现控制台

完整实现控制台的日志显示和代码执行功能。

阶段三: 实现元素审查

阶段四: 源代码调试

阶段五: 网络监控
